# `vibeslayer-policy-kit` (`0.6.0-beta.1`)

[← Root README](../README.md) · [Web & Web Components Guide](../docs/web-and-web-components.md)

Source-configured per-action protection boundary for Node.js (`>=20.0.0`, zero external dependencies), now including **`antiStealth: "off" | "balanced" | "strict"`** on `definePolicy`, per-action overrides, `createGateway`, and `createClient` to deny anti-detect browsers (e.g. CloakBrowser) and headless automation on Web Component and API actions.

## 1. Source Configuration

Developers configure every action and parameter rule directly in code via `definePolicy(...)`:

- `enabled`: defaults to `false`; no action executes until explicitly set to `true`.
- `mode`:
  - `public-preview`: serves only a coarse releasable proxy (for example an 800-byte bounding-box `.glb` generated by `buildBoundingBoxPreviewGlb`, containing `0` bytes of the original `EXT_meshopt_compression` mesh stream).
  - `server-only`: validates parameters, origin, HMAC-SHA256 lease signature, scope, replay count (`maxUses`), and rate limit on the server; strips `redactFields` before serializing JSON.
  - `client-sealed`: encrypts full bytes with `AES-256-GCM` + action/lease `AAD` (`sealAssetAes256Gcm`). Blocks offline static extraction of a stolen ciphertext bundle when no lease key is present; once an authorized client receives `leaseKey` and unseals locally, a user controlling that live client can capture the plaintext bytes.
- Per-parameter schema (`params`): `int`, `number`, `string` (`minLength`, `maxLength`, `pattern`), `boolean`, `enum`, `optional`. Unexpected keys fail with `UNKNOWN_PARAM`.

## 2. Security Comparison vs. Unprotected Client Code & LLM Agents

| Mode | Static / Offline Bundle Theft | Live Browser / Memory / DevTools Hook + Unlimited-Time Flagship LLM | Hot-Loop Frame Overhead |
| :--- | :--- | :--- | :--- |
| **Unprotected client bundle** | Full logic, secrets, and `581,260 B` `.glb` trivially copied | Full extraction | `0` ops/frame |
| **`client-sealed` (`AES-256-GCM` + lease AAD)** | Ciphertext-only thief without lease key gets **0 plaintext bytes** (authenticated encryption, not custom obfuscation) | **Extractable** at or after legitimate client unsealing / GPU upload (`581,260 B` recovered in benchmark) | `0` ops/frame after one-time `~4.5 ms` unseal |
| **`server-only` + `public-preview`** | Thief gets only the `800 B` bounding-box proxy (`0.14%` of original size, zero original mesh bytes) | **Unrecoverable** from client regardless of LLM runtime or token budget because secret fields and full geometry never leave the server | `0` ops/frame (`~0.55 ms` localhost HTTP per action) |

### Why client-side obfuscation cannot make local plaintext unextractable

Flagship coding/RE agents do not rely only on reading variable names or static ASTs:
1. Prompt-injection strings or fake comments inside binaries/JS are ignored when the agent writes a 15-line script to dump runtime buffers.
2. Opaque predicates, custom sponges, WASM wrappers, and decoy keys only tax **static** comprehension; in a controlled browser or Node/native runtime, hooking `Response.arrayBuffer`, `TypedArray`, `WebAssembly.instantiate`, or `gl.bufferData` captures the exact unsealed bytes after your own loader finishes.
3. Therefore, the only element an unlimited-time LLM **cannot** extract from the client is data that **never enters client memory** (`server-only` / server-rendered / coarse `public-preview`), while `client-sealed` (`AES-256-GCM`) is the right cryptographic boundary against **offline CDN/bundle scraping** without authorization.
